# GMS 시세 정기 수집

일반 Chrome 확장 프로그램 → 검증된 매물 → 인증된 Worker 수신부 → D1.
수집 과정은 일반 JavaScript로 실행되며 AI API를 호출하지 않습니다.

## 현재 운영 설정 — v0.3.0 (2026-11-10 KST)

서버는 **1시간 간격 · 회당 최대 50건 · UTC 하루 최대 1,200건**으로 변경했습니다. 새 수집 계획은 이전 계획의 하루 최대 48,000건보다 입력량이 97.5% 적습니다. 입력량은 실제 D1 `rows_written`과 같지 않으며 인덱스·스캐너·기타 기능 비용은 따로 합산됩니다.

- 설치된 v0.2.3의 15분 예약은 다시 켜지 않습니다. 설치 폴더를 v0.3.0으로 갱신한 뒤 Chrome 확장 관리에서 새로고침해야 합니다.
- v0.3.0은 과거 15분 알람을 지우고, 수집 전에 인증된 서버 사전 확인을 거칩니다. 일일 한도/최소 간격에 걸리면 원본 사이트 창을 열거나 조회하지 않고 다음 허용 시각까지 대기합니다.
- 기존 수집 기록은 삭제하거나 사용량 계산에서 제외하지 않습니다. 당시 당일 입력 7,035건은 새 한도보다 많아서 한국 시간 오전 9시(UTC 00:00) 초기화 후 재개합니다.
- 수동 실행, 재시작, 실패 복구에도 최소 1시간 간격을 적용합니다. 한 실행에서 아이템 최대 12종, 상점 최대 120곳을 조회하고, 유효 매물 50건이 모이면 종료합니다. 상점 확인 사이에는 1초를 둡니다.
- 새 배치 이력은 `listing_history`에만 저장하고 과거 `market_observations`는 읽기 전용으로 보존합니다. 중복 관측과 동일 실행 재전송은 중복 저장하지 않습니다.
- `GET /market/status`는 마지막 실제 저장 시각, 수집 간격, 한도 대기/일시 중지/지연을 공개합니다. 메인과 시세 화면은 이 값으로 상태를 표시하며 목록 새로고침 시각을 수집 시각으로 사용하지 않습니다. 3분 edge 캐시와 날짜 인덱스로 조회 비용을 제한합니다.
- 정상 HTTP 응답만으로 수집기가 온라인이라고 판단하지 않습니다. 마지막 저장이 1.5회 수집 간격보다 오래되면 지연으로 표시합니다.
- 현재 예약 설정은 Chrome과 수집 창이 열린 컴퓨터에서 실행됩니다. 절전/종료/접근 확인 상태에서는 지연될 수 있으며 이 경우 실제 저장 시각이 갱신되지 않습니다.

서버 반영: Worker `c959c91a-84c8-4e99-82d0-3f7d4a0680ca`. 운영 사전 조회에서 `daily_budget`, 기존 7,035건, 다음 허용 시각 2026-11-10 09:00 KST를 확인했습니다. 상태 조회는 MISS → HIT였으며, 날짜 인덱스 적용은 실제 32행 읽기·16행 쓰기였습니다.

아래 v0.2.2/v0.2.3의 500건·15분 운영 내용은 과거 검증 기록입니다. 현재 설정으로 사용하지 마세요.

## 실행

확장 관리 화면에서 ‘GMS 시세 자동 수집’을 새로고침한 뒤 메소워치 페이지를 새로고침합니다. 패널에 **v0.3.0 / 1시간 간격 / 최대 50건**이 표시되는지 확인합니다.

- **1시간 자동 수집 켜기**: 저장된 최소 간격에 맞춰 예약을 시작합니다. 한도에 걸리면 원본 사이트를 읽지 않고 초기화까지 기다립니다.
- **최대 50건 수집·저장**: 같은 서버 한도와 로컬 최소 간격을 따릅니다. 수동 실행으로 제한을 우회할 수 없습니다.
- **자동 수집 끄기 / 실행 중지**: 각각 예약만 중단 / 진행 중 실행과 예약 중단입니다.
- **저장 재시도 / 결과 JSON 저장**: 보관된 결과 재전송 / 민감정보 없는 증빙 다운로드입니다.
- **반복 검증 3회**: 개발 검증 전용이며 DB에는 쓰지 않습니다. 운영 수집을 대신하는 예약이 아닙니다.

확장이 만든 별도 수집 창은 사용자 탭을 이동시키거나 포커스를 가져오지 않습니다. 수집 창을 최소화하지 마세요. 사이트의 상점 목록이 뜨지 않으면 아이템별 최대 두 번 확인 후 건너뜁니다. 전체 실패 시 한 시간 후 다시 시도하며 접근 확인 화면은 자동 중단합니다.

## 데이터 보호와 검증

- 정확한 아이템 ID/이름·개당 가격·판매자·채널·자유시장 방·원래 관측 시각을 확인합니다.
- 최근 3시간의 판매 중 매물만 수용하며 날짜가 자정을 넘어도 실제 관측 시각을 보존합니다.
- 위치 누락, 묶음/세트 가격, 수량 1이 아닌 항목, 판매 완료, 목록/상세 불일치는 제외합니다.
- 불완전하게 종료된 실행은 업로드하지 않습니다.
- 요청 전체를 검증하고 하나의 D1 트랜잭션으로 저장합니다.
- `listings`는 더 최신인 시각만 갱신합니다. 최초 관측과 이미 확인된 판매 완료 상태는 유지합니다.
- 기존 `market_observations`는 보존하되 새 쓰기는 하지 않습니다. 신규 이력은 `listing_history`에만 저장합니다.
- 동일 실행 재전송과 같은 매물 재관측은 중복 행을 만들지 않습니다.
- 429/네트워크/5xx는 저장 대기함에서 최대 3회 시도합니다. 401/403/검증 오류는 자동 중단합니다.
- 인증 키는 `config.private.js`에만 두며 Git과 다운로드 보고서, 페이지 DOM에 포함하지 않습니다.
- 공개 페이지의 출처 표시는 변경하지 않습니다.

## 설치/서버 구성

1. `worker/migrations/0001_market_batch.sql`과 `0003_market_batch_usage_index.sql`을 D1에 적용합니다. 기존 행은 변경하지 않습니다.
2. 수집 전용 랜덤 키를 Worker secret `MARKET_BATCH_TOKEN`에 등록합니다.
3. Worker를 배포합니다. 수신 경로는 `/internal/market-batch`입니다.
4. `extension/config.example.js`를 비공개 설치 폴더의 `config.private.js`로 복사해 같은 키를 설정합니다.
5. 기존 확장 설치 폴더에 `extension/` 파일을 반영합니다. `config.private.js`는 보존합니다.
6. Chrome 확장 관리 화면에서 사용자가 새로고침합니다. 접근 범위는 메소워치와 GMS Hub Worker 두 도메인뿐입니다.
7. 3회 검증 후 수동/예약 적재 및 중복 재전송을 확인하고 예약을 켭니다.

관리 조회: 같은 Bearer 키로 `GET /internal/market-batch` 요청 시 최근 서버 적재 20회를 조회합니다.
공개 시세 순위는 Worker 예약 작업이 15분마다 재계산합니다.
실시간 시세의 가격 추이는 보존된 배치 이력과 `0002_listing_history.sql`의 공통 관측 이력을 중복 없이 사용합니다. 매물대는 현재 매물 행만 집계합니다.
