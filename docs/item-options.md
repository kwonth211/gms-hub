# 장비 옵션 (상옵·하옵·작) 설계

수집기가 읽은 장비 옵션을 사이트가 받아 저장하고 보여 주는 규칙이에요.
macOS 고확 수집기는 게임이 백그라운드에 있을 때 링크를 클릭하고 툴팁에서 읽은 `opts`를 고확 본문과 함께 보내요.

## macOS 고확 수집

- 2026-11-20 운영 중단 상태: 자동 입력 뒤 사용자 커서가 사라진다는 보고가 있어 `~/.config/gms-hub/mega-options-paused` 파일로 옵션 입력을 차단했어요. 채팅 텍스트 수집·전송은 유지해요. 이 파일은 설치나 재시작으로 지우지 않아요. 커서 위치·포커스 검사만으로 커서 표시 상태와 게임 조작 무간섭을 보장할 수 없으므로, 기존 입력 방식을 검증 없이 다시 켜지 않아요.

- `scripts/scan-tools/mega.sh install <체크아웃>`으로 운영 수집기를 설치·재시작해요. 옵션 읽기는 기본 활성화이며 `node mega-collector.mjs --no-options`로 끌 수 있어요.
- 화면 녹화와 손쉬운 사용 권한이 필요해요. 창에 직접 보내는 이벤트로 게임 내부 포인터만 움직이고, 실제 마우스와 다른 앱의 포커스는 유지해요. 게임이 전면이거나 마우스 버튼을 누르고 있으면 건너뛰어요.
- 새 고확 중 링크가 하나인 장비·주문서를 대상으로 읽어요. 클릭 전후 닉네임·채널, 창 크기와 툴팁 이름을 확인하고 장착 장비의 비교 패널은 제외해요.
- 닉네임·귓속말 버튼 영역을 벗어난 링크만 클릭해요. 기존 귓속말 창이 열려 있으면 건너뛰고, 수집기의 클릭 직후 새로 열린 귓속말 창은 취소해요.
- 원본·확대 마스크를 macOS Vision으로 읽어요. 두 결과의 숫자가 충돌하거나 읽기 불명확하면 해당 값은 보내지 않아요. 모든 고확의 옵션을 보장하지 않으며 실패한 고확도 본문은 계속 전송해요.
- 옵션은 대괄호로 **링크한 아이템**의 수치예요. `B>` 본문에서 별도로 구하는 아이템의 수치가 아니에요.
- 서버에는 텍스트와 숫자만 보내고 캡처 이미지는 보내지 않아요. 채팅 캡처·진단 로그는 기존 로컬 경로를 사용해요.
- 업로드 없는 확인: `node mega-collector.mjs --dry --options --duration=60`. `--dry`만 사용하면 클릭 없이 본문만 읽어요. 운영 옵션 수집기와 클릭 테스트를 동시에 실행하지 않아요.

## 용어 (유저들이 쓰는 뜻 그대로)

- **정옵:** 드롭 장비의 주 능력치가 게임 데이터의 기본값과 같은 것.
- **N상 / N하:** 주 능력치가 기본값보다 N 높으면 "N상"(1상~5상), N 낮으면 "N하". 상옵·하옵은 이걸 통틀어 부르는 말.
- **주 능력치:** 무기는 공격력(완드·스태프는 마력), 방어구는 물리방어력(없으면 마법방어력). 여러 능력치를 합치지 않아요.
- **+N (아이템 이름 앞):** 주문서 성공 횟수. 예) +3 태극부채
- **업횟:** 남은 업그레이드 가능 횟수. 실패 = 쓴 횟수 − 성공.
- **노작:** 주문서를 한 번도 안 바른 장비. 정옵·N상·N하는 노작일 때만 말할 수 있어요(작하면 주문서 수치가 섞여요).
- 요즘 메이플의 추옵(추가옵션)·잠재능력은 클래식 월드에 없어서 쓰지 않아요.

## 보내는 형식

매물 한 줄(또는 확성기 한 줄)에 `opts` 하나를 더해요. 모르는 값은 빼고 보내요.

```json
{
  "stats": { "PAD": 9, "LUK": 2 },
  "slots": 5,
  "used": 2,
  "ups": 1,
  "clean": false
}
```

| 필드 | 뜻 | 값 |
|---|---|---|
| `stats` | 게임 툴팁에 보이는 능력치 그대로(기본 흔들림 + 작 포함) | 정수. 0인 값은 빼요 |
| `slots` | 남은 업그레이드 가능 횟수 | 0–20 |
| `used` | 이미 쓴 업그레이드 횟수(성공+실패) | 0–20 |
| `ups` | 주문서 성공 횟수. 게임에서 이름 옆에 붙는 `(+N)` | 0–20, `used`보다 클 수 없어요 |
| `clean` | 작을 한 번도 안 했는지 | `true` / `false` |
| `attackSpeed` | 툴팁의 공격 속도 | `very fast`, `fast`, `average`, `normal`, `slow`, `very slow` |
| `knockback` | 넉백 확률 (%) | 0–100 |
| `scroll` | 주문서의 성공률·증가량. 장비 총 능력치와 구분 | 예: `{ "chance": 60, "stats": { "PAD": 2 } }` |

`stats` 이름은 게임 데이터 이름 그대로 써요. 사이트 전체(아이템 정보, 작 시뮬레이터)가 같은 이름을 써요.

| 이름 | 한국어 표시 | 영어 표시 |
|---|---|---|
| PAD | 공 (공격력) | ATT |
| MAD | 마 (마력) | M.ATT |
| STR · DEX · INT · LUK | 힘 · 덱 · 인 · 럭 | STR · DEX · INT · LUK |
| ACC · EVA | 명중 · 회피 | ACC · AVOID |
| MHP · MMP | HP · MP | HP · MP |
| PDD · MDD | 물방 · 마방 | DEF · M.DEF |
| Speed · Jump | 이속 · 점프 | SPEED · JUMP |
| CRT · CRD | 크확 · 크뎀 | CRIT · C.DMG |

## 어디로 보내나

- **상점 매물:** 지금 수집기가 쓰는 `POST /internal/market-batch`의 `rows[]` 각 줄에 `opts`를 더해요. 나머지 필드와 인증은 그대로예요.
- **게임 안 상점 수집기:** `POST /internal/shop-scan`의 `rows[]` 각 줄에도 같은 `opts`를 더해요. 장비에 마우스를 올려 뜨는 설명창에서 읽어요.
- **확성기:** `POST /internal/megaphone`의 `rows[]` 각 줄에 `opts`를 더해요.

## 서버가 하는 일 (`worker/src/item-options.js`)

- 목록에 없는 이름, 정수가 아닌 값, 범위 밖 값은 버려요. 옵션이 이상해도 그 매물 자체는 정상으로 저장해요.
- "클린"인데 `used`가 1 이상이면 "클린"만 빼요.
- 매물 줄의 `opts` 칸(JSON 글자)에 저장해요. 같은 줄에 붙여서 데이터베이스 쓰기가 늘지 않아요.
- 같은 매물이 다음 수집 때 옵션 없이 오면 이전 옵션을 유지해요.
- 같은 판매자·채널·방·가격의 같은 아이템 두 개는 지금 구조상 한 줄로 합쳐져요. 이 경우 나중에 온 옵션이 남아요.

## 화면

- **확성기:** 링크한 아이템 아래에 작·옵션 등급과 실제 능력치, 남은 강화 횟수(0 포함), 공속·넉백을 표시해요. 주문서는 성공률과 증가량을 표시해요. 아이템 링크의 기존 상세 카드에도 읽은 장비 옵션을 전달해요. 상단 고확 띠에도 작 성공 횟수와 같은 옵션 수치를 본문 옆에 표시해요.
- **옵션 미확인:** 실제 옵션이 없는 장비 고확은 목록과 마우스 카드에서 미확인으로 표시해요. 카탈로그 기본 능력치나 기본 강화 횟수로 대신 채우지 않아요. 띠의 아이템 이름과 옵션 숫자는 같은 옵션 카드를 열어요.
- **실시간 전달:** 서버 저장과 WebSocket 전송 모두 같은 `opts`를 포함해요. 노란색(Y)·파란색(C) 아이템 고확만 옵션 수집 대상으로 삼고, 같은 닉네임·채널·본문이 화면에 남아 있으면 순환 재시도해요. 이미 전송한 글은 원래 시각까지 일치할 때만 빈 옵션을 보충하고, 띠와 목록도 같은 ID를 갱신해요. 기존 옵션을 덮어쓰거나 거래 알림을 다시 보내지 않아요. 수집 실패 사유는 운영 수집기 로그에 남겨요. 게임이 전면인 상태의 자동 클릭은 현재 차단되며, 화면 OCR은 가림·잘림·움직임 때문에 전체 고확 100% 인식을 보장하지 않아요.
- **커서 복귀 검증(2026-11-20):** 기존 입력 후 커서 표시가 1→0으로 남는 현상을 재현했어요. 게임 창에 연결한 `mouseMoved`를 실제 포인터 위치로 보내 Wine의 커서 소유 상태를 해제하면 0→1로 복귀했어요. 수정 입력 10회 연속에서 실제 좌표·포커스·표시 상태 유지 확인. 창 번호 없는 이벤트는 복구 효과가 없었어요. 보이던 커서가 숨겨지면 자동 옵션 입력을 일시 중지해요.
- **수집 누락 조사(2026-11-20 22시):** 일부 성공 사례는 전체 수집 성공률을 뜻하지 않아요. 기존에는 OCR 문장이 조금만 바뀌어도 대기 작업을 삭제했고, OCR 중 채팅이 밀리면 이전 좌표만 검사해 포기했어요. 지금은 닉네임·채널·본문을 포함한 줄의 픽셀 지문으로 같은 줄을 재탐색하고, 일치하는 줄이 하나일 때만 클릭해요. 새 대상의 첫 시도를 반복 실패 대상보다 우선해요. 장비 정보가 없는 항목은 수치를 못 읽었을 때 반복 클릭하지 않지만, 정보가 없다는 이유로 캐시 아이템이나 무옵션이라고 단정하지 않아요.
- **옵션 OCR 보완:** 반투명 툴팁의 Type부터 Remaining Enhancements까지를 좁게 잘라 배경 채팅·착용 조건·하단 UI의 간섭을 줄여요. 마스킹한 본문을 Vision과 Tesseract로 읽고, 신뢰 가능한 수치가 서로 다르면 그 필드는 버려요. 실제 Emerald Earrings 캡처에서 기존에 빠졌던 STR 3과 MDD 27·CRD 2·강화 +2·잔여 0을 확인했어요. 한 필드라도 붙은 건수와 모든 필드를 정확하게 읽은 건수는 별개예요.
- **복구 한계:** 이미 화면 밖으로 사라지고 옵션도 저장하지 못한 과거 고확은 이 수정만으로 복구되지 않아요. 기존 미확인 글은 띠에 다시 재생될 수 있어요. 수집기는 여전히 한 건에 약 3~4초가 필요하고 전면 게임 자동 입력을 차단하므로, 모든 고확의 무간섭 100% 수집이 완료된 상태가 아니에요.
- **기존 상점 코드 대조(2026-11-20 22:32):** `~/gms-hub-shop/shop.py`의 `careful_read`는 짧게 기다린 뒤 툴팁 근처를 읽고, 실패할 때만 대기·확대를 늘려요. `vis.swift`의 원본 색상·고품질 2배 확대를 `maple-ocr.swift`에 재사용했어요. 마스킹만 하면 숫자 획을 지울 수 있으므로 원본 확대와 마스킹을 함께 읽고, 기본 판독에서 능력치·잔여 횟수를 확보하면 Tesseract 재시도는 생략해요. 직접 클릭한 구룡도는 84/+3/잔여 0, 기존 메바 캡처는 20/+1/잔여 6, 에메랄드 귀고리는 STR 3·MDD 27·CRD 2/+2/잔여 0을 대조했어요. 상점의 `inp.swift`는 전역 마우스 입력이고 실제 커서를 쓰므로 운영용 백그라운드 입력에는 그대로 사용하지 않아요.
- **고확 아이템 클릭:** 상단 띠와 고확 목록 모두 `opts` 조건을 붙여 매물을 열어요. 읽은 능력치, 남은 강화 횟수, 성공 횟수가 모두 같은 매물만 서버에서 조회해요. 0도 조건에 포함하며 모르는 값은 일치로 취급하지 않아요. 주문서는 아이템 ID로 구분하므로 증가량을 장비 필터에 넣지 않아요. 적용 조건을 표시하고 한 번에 해제할 수 있어요. 링크 복사·새로고침에도 유지되고 다른 아이템에는 넘어가지 않아요. 대표 시세·차트는 전체 옵션 기준이에요.
- **시세 → 아이템 → 판매 매물, 전체 매물, 매물대, 홈의 방금 올라온 매물:** 한 단어만 붙어요(`assets/opt-grade.js`).
  - 작한 장비: `+3` (주문서 성공 횟수)
  - 노작 장비: 주 능력치로 `정옵` / `2상` / `1하`
  - 옵션이 없거나 기본값을 모르는 장비는 아무것도 안 붙어요. 회피·MP 같은 개별 능력치는 칩에 쓰지 않아요.
  - 매물에 마우스를 올리면 기존 아이템 카드가 그 매물의 옵션 전체(능력치, 업횟, 성공·실패)로 떠요.
  - 기본값은 `node scripts/fetch-item-details.mjs --ids <파일>`로 채워요.
- **옵션별 시세:** 옵션이 있는 매물이 두 종류 이상이면 매물 위에 "옵션별 시세" 표가 생겨요. 같은 단어(정옵·2상·+3…)끼리 묶어서 가장 싼 값과 개수를 보여 줘요.
- 옵션이 없는 매물과 확성기는 지금과 똑같이 보여요.
